The meaning comes in three forms, so that the experiment can tell the form apart from the content, and a decoy that carries none of it. Each file links to its source on GitHub.

- **[`ontology.ttl`](https://github.com/lambdamusic/semantic-ladder-demo/blob/main/domains/credit/ontology/ontology.ttl)**: three classes, the properties each CSV column names, and every code as a SKOS concept, with its `skos:notation` as it appears in the data. The meaning is in plain-English `skos:definition`s.
- **[`ontology.md`](https://github.com/lambdamusic/semantic-ladder-demo/blob/main/domains/credit/ontology/ontology.md)**: the same definitions as Markdown, generated from the Turtle by [`ontology_to_md.py`](https://github.com/lambdamusic/semantic-ladder-demo/blob/main/src/ontology_to_md.py) so that the two never drift. This is what the `csv+markdown` and query conditions get, and it's shown below.
- **[`axioms.ttl`](https://github.com/lambdamusic/semantic-ladder-demo/blob/main/domains/credit/ontology/axioms.ttl)**: the meaning as logic, with no prose. OWL keys, functional properties, disjoint classes and code lists as classes, plus SHACL-AF rules that derive what the definitions say: identity by LEI, domicile, parent chains entity by entity, rating periods, ratings in force, credit risk, and a constraint that catches a rating above its ceiling. The `csv+axioms` condition gets these plus the ontology with its definitions removed. `sparql+axioms` queries the data after the rules have run.
- **[`padding.md`](https://github.com/lambdamusic/semantic-ladder-demo/blob/main/domains/credit/ontology/padding.md)**: the decoy glossary for `csv+padding`. It's on the same subject, bond markets, and as long as `ontology.md`, but defines none of the terms the questions depend on.

[`check_axioms.py`](https://github.com/lambdamusic/semantic-ladder-demo/blob/main/domains/credit/check_axioms.py) runs the rules over the data and checks their output against the keys, so the logic is tested as well as read.
