## The data

You can't see the data, but you can query it. It is in DuckDB, in the tables below. Write DuckDB SQL.

To run queries, reply with one or more fenced blocks (```sql), and nothing else is needed:
each is run and its results sent back to you. You have up to 8 rounds of queries.
When you have what you need, reply with the final answers and no queries.

All columns are text (VARCHAR); dates are ISO strings.

- `works` (80 rows): work_id, title, year, type, source_id, retracted, research_output, record_ids
- `people` (36 rows): person_id, name, orcid, author_ids
- `credits` (130 rows): work_id, person_id, institution_id
- `institutions` (18 rows): institution_id, name, ror, country, type, parent_id
- `institution_units` (26 rows): institution_id, counts_towards, levels_up
- `sources` (8 rows): source_id, name, issn, type, tier, tier_rank, delisted
- `citations` (66 rows): citing_work_id, cited_work_id

These tables are the data after its rules have been applied. Test records are gone. A preprint is merged into its published version (record_ids lists the records each work merges). research_output says whether a work counts as research output. Author records are merged into people (author_ids lists them). credits gives the one institution credited for each person on each work. institution_units lists every institution each institution's works count towards, itself included, with how many levels up. citations links merged works, and only from citing works that count. tier_rank ranks journal tiers, 1 the highest; a delisted source's works are not research output.
